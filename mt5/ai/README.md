# TbotAI: machine-learning bot for the 1-minute chart

## What it is

`TbotAI.mq5` runs a small neural network inside MT5 using MetaTrader's built-in ONNX support. On every new M1 bar it looks at the last 240 closed bars and turns them into 17 numbers: recent returns, distance from moving averages, candle shape, RSI, volatility regime, and position in the recent range. From those it estimates three probabilities for the next 60 minutes:

- **P(up)**: price rises by B before it falls by B
- **P(down)**: price falls by B first
- **P(none)**: neither happens

B is 3 × ATR(14) by default. The EA buys when P(up) passes your confidence threshold and beats P(down) by a margin, and sells on the mirror condition. Stop loss and take profit are both B. A trade still open after 60 bars is closed. The same risk controls as TbotAdaptive apply: risk % per trade, daily loss limit, max trades per day, cooldown after a losing streak, and a spread filter.

The model is trained in Python (`train.py`) on history exported from your own MT5 terminal. It is tested **walk-forward**: train on 12 months, test on the next 3 months it has never seen, roll forward, repeat. The out-of-sample numbers go into `TbotAI_config.json`. Those are the numbers to believe, not the training accuracy.

**Mode** works as in TbotAdaptive. *Signals only* (the default) draws the entry, SL and TP on the chart and sends a pop-up alert plus a push notification to your phone. Each signal includes the model's confidence and a suggested lot size, and after a signal the bot waits 60 bars before the next one. *Auto trade* places and closes the trades itself. Phone notifications and logging into your Deriv MT5 account are covered in `../README.md`.

## Read before using: what the tests showed

See `RESULTS.md` for the actual numbers. In short:

- **Deriv synthetic indices (Volatility 75 etc.)**: Deriv states these are generated by a random number generator with fixed volatility. Past bars carry no information about future bars, so no model, however clever, can predict them. On a faithful simulation the model came out at coin-flip level, as it should.
- **Forex on M1**: real markets can carry small patterns, but on one-minute bars the spread is a large share of every move, so it eats most of any edge.

Treat this as a research tool. Only run it live if *your own* walk-forward test on *your broker's* data shows a positive net result across most folds, and a demo run agrees.

## Files

| File | What it is |
|---|---|
| `TbotAI.mq5` | The Expert Advisor (embeds `TbotAI.onnx` when compiled) |
| `TbotAI.onnx` | Trained model (EURUSD M1, trained on the most recent 12 months of the test data) |

| `fetch_deriv_m1.py` | Optional: download M1 candles from Deriv's public API |

## Retrain on your own symbol

1. **Export data.** Copy `ExportBars.mq5` to `MQL5\Scripts\`, compile it (F7), open an M1 chart of the symbol, and drag the script onto it. It writes `MQL5\Files\<Symbol>_M1.csv`. Use as much history as your terminal holds (Tools → Options → Charts → Max bars in chart). At least 12–18 months is needed.
2. **Install Python 3.10+**, then run:
   `pip install numpy pandas scikit-learn skl2onnx onnxruntime`
3. **Train and test** (in the folder with `train.py`):
   `python train.py --data "Volatility_75_Index_M1.csv" --spread 0 --out TbotAI`
   - `--spread` is the round-trip cost in price units. Check the spread in Market Watch and enter it, because a 0 spread flatters results.
   - `--barrier 3 --horizon 60` set the target (SL = TP = 3 × ATR, max 60 bars). Bigger targets make spread matter less.
   - Watch the per-fold lines and the **OUT-OF-SAMPLE SUMMARY**. If `avg_net_R` is not clearly above 0 across most folds, the model has no usable edge on that symbol.
4. **Load it into MT5.** Copy `TbotAI.onnx` next to `TbotAI.mq5` in `MQL5\Experts\`, then compile `TbotAI.mq5`. Set the EA inputs from `TbotAI_config.json`: `Threshold` = `suggested_threshold`, plus `BarrierATR` and `HorizonBars`. If `suggested_threshold` is null, the model found nothing worth trading.
5. **Backtest in the Strategy Tester** on a period *after* `trained_to` in the config, with "Every tick based on real ticks". Testing on the training period means nothing.
6. **Demo for several weeks**, then decide.

Retrain every 1–3 months so the model reflects recent behaviour, and always re-check the walk-forward summary each time.

## Debugging

Set `LogFeatures = true` to print the 17 features and the three probabilities every bar in the Experts log. If OnInit fails with an ONNX error, the `.onnx` file wasn't next to the `.mq5` at compile time, or it was exported with a different number of features.
